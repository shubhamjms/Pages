What is Copilot?

Understand where a copilot helps, what Copilot Studio adds, and how a useful agent connects language to action.

12 MIN / BEGINNER / FUNDAMENTALS

On this pagePurposeWorking flowBoundaries

A copilot is useful when it helps someone move from a question to a grounded decision or action. The language model supplies flexible understanding; the surrounding system supplies context, permissions, tools, and evidence.

Begin with a useful purpose

Start with one job the reader can recognize. Name the information the agent needs, the action it may take, and the evidence it should return. A narrow purpose is easier to test than a broad promise.

Field note

A fluent answer is not the finish line. The useful unit is an answer connected to context, action, and visible evidence.

A working flow

The platform joins conversational input to governed data and capabilities. Each transition should remain inspectable.

Choose the smallest capability

Use knowledge for grounded explanation, an action for a controlled change, and a topic when the conversation requires a deliberate sequence.

CapabilityUse it forEvidence to keep
KnowledgeGrounded explanationSource citation
ActionControlled operationResult and status
TopicStructured dialogueCollected values

Keep the boundary explicit

Instructions should say what the agent can do, what it must not infer, and when a person needs to review the result.

Goal: Help a maker find a grounded next step.
Use: Approved product knowledge and named actions.
Never: Invent records, permissions, or completion status.
Return: Answer, source, action result, and next review point.

Learning/Dataverse extensions/Part 1

Extension landscape

Choose the smallest supported Dataverse extension point that satisfies the requirement and remains operable.

11 MIN / INTERMEDIATE / FOUNDATIONS

On this pageContractOptionsRelease check

An extension should make a platform capability clearer, safer, or more efficient. Begin with the supported contract, then decide whether the behavior belongs in metadata, a custom API, a plug-in, or the app surface.

Start from the contract

Write down the triggering event, required inputs, expected output, security context, and failure behavior before choosing an implementation point.

Field note

The most powerful extension is not automatically the best one. Prefer the least invasive supported mechanism that keeps ownership visible.

Compare the options

Extension pointBest fitPrimary boundary
Custom APIExplicit reusable operationRequest and response contract
Plug-inServer-side event behaviorPipeline stage and security context
App moduleFocused user experienceNavigation and table access

Keep the release reviewable

Package only the required components, version the output, and verify permissions in the target environment before enabling dependent workflows.

trigger: explicit operation
inputs: accountId, requestedState
security: caller context
output: status, changedFields
failure: typed platform error
